# 从新终端开始操作

## 日常使用：一个终端加一个浏览器

在新终端执行：

```bash
cd multi_robot
./run.sh
```

这个终端持续运行即可，不要同时再启动旧教程的三车脚本或重复运行本工程。浏览器打开 `http://127.0.0.1:8765`。Gazebo 是三维物理场景；网页是本项目的任务控制与地图显示。

启动期间车辆保持静止。系统会等待雷达、里程计、SLAM、地图坐标标定、机器人周围的空闲观测和三套导航实际就绪。网页进入“待命”后才开始下发任务。

网页地图只画激光观测生成的共享图：浅色是已观测空闲，深色是障碍，灰蓝色是未知。每格 1 米；正 X 朝右，正 Y 朝上。三条彩色轨迹表示估计轨迹，三台车的颜色一一对应。

## 第一次探索

1. 如需改分区，先展开“开始前调整分区”。每行依次为 `xmin ymin xmax ymax`，单位米。
2. 场地为 15×15 m；默认区域分别是 `[-7.5,-7.5,-2.5,7.5]`、`[-2.5,-7.5,2.5,7.5]`、`[2.5,-7.5,7.5,7.5]`，起点分别为 `(-5,-5)`、`(0,-5)`、`(5,-5)`。
3. 三块矩形必须覆盖场地、不重叠、包含各自起点。点击“应用区域”会得到接受或拒绝原因。
4. 点击“开始 / 恢复探索”。不需要人工指定巡航航点。
5. 可观察各车轨迹、探索里程和地图变化。“已观测比例”只是栅格统计；正式覆盖率需要独立评估器计算。
6. “暂停停车”停止任务，但保留本轮地图和定位。“开始 / 恢复探索”会重新选择前沿。

首次探索、巡逻或队形任务后区域锁定；重新划分请结束本轮并重启。探索时机器人根据未知边界选目标，地图逐步成熟时也可能暂时等待新的有效空闲观测。发现本区探索目标需要经过区外的已知安全通路才能到达，且情况持续至少 8 s 时，会自动解除分区并显示原因。固定航点任务请使用“航点巡逻”面板，详见 [项目 README](../README.md#新增分区航点巡逻)。

## 随机种子与复现场景

`./run.sh` 默认每次生成新场景，网页和启动终端会显示种子。使用 `./run.sh --seed 42` 可复现种子 42 的场景。相同种子、生成器版本及配置得到相同障碍布局；SLAM 结果和行驶轨迹不承诺逐帧一致。默认版本 `mixed-shapes-v2` 包含旋转矩形、凸/凹多边形、圆形、扇形各 2 个，生成时检查通路连通性并保护起点与中央集合空间。新旧版本的同一数字种子对应不同地图；旧矩形场景使用 `./run.sh --seed 24 --scene-generator rectangles-v1`。详情和多种子预览见 [README](../README.md#随机场景预览版2026-10-26)。

## 集合与三种队形

确保中央目标区域已经显示为空闲。填写中心 X、中心 Y、朝向和间距，然后选择队形并点击“切换至指定队形”。

| 队形 | 朝向为 0 时的排列 | 默认间距 |
|---|---|---|
| 等边三角形 | 前顶点朝右，另两点在左上 / 左下 | 边长 1.2 m |
| 横排 | 竖向排列在局部 Y 轴 | 相邻 1.2 m |
| 纵队 | 横向排列在局部 X 轴 | 相邻 1.2 m |

“横排 / 纵队”相对于队形朝向定义，不是固定相对于屏幕。朝向 `1.5708 rad` 相当于把整个队形逆时针旋转约 90°。目标是地图的绝对坐标，不是相对于机器人当前位置的偏移。

系统会检查目标、取消探索、停车、解除分区限制、分配位置，再让车辆分步到位。先停着的两台车是在等待其轮次。显示“队形就绪”才代表三车误差检查已持续通过 3 秒；服务显示“请求已接受”只是开始执行。

队形目标落在未知、障碍或安全余量不足的区域时会被拒绝，原任务不会因此被接管。先探索该区域，或调整中心 / 间距。

切换三角形 → 横排 → 纵队后，可以再次点击“开始 / 恢复探索”：未解除分区时先返回各自分区；已经自动解除分区时直接继续跨区探索。跨区阶段轮流执行目标，其他车辆等待通行，以减少在共享通道中相遇的风险。

## 停车、故障与退出

- 普通暂停：点“暂停停车”，地图与定位继续运行。
- 急停：点红色按钮，锁定持续零速度并取消任务。
- 解除急停：仅回到待命，不自动恢复运动，需要重新发任务。
- 雷达、定位、导航内部位姿或关键节点心跳异常：系统进入故障停车；先查看网页原因和运行日志。
- 关闭网页不会停后台。退出整个工程请在启动终端按 **Ctrl+C**。
- Gazebo 的暂停按钮暂停的是物理时间，不等于本项目的任务急停。日常停止任务请使用网页按钮。

正常验收使用静态场地，不要在导航中拖动机器人、删除墙体或增删障碍物。场景编辑也不会自动保存成机器人地图或持久世界文件。

## 保存和下次查看

点击“保存地图与运行结果”，或在可选控制终端指定目录：

```bash
cd multi_robot
source ./env.sh
ros2 run fleet_control fleetctl save --output results/my_map
```

保存包含共享 PGM/YAML、三份 PBStream、坐标对齐、分区、任务快照、日志采样及在线指标。PBStream 服务完成情况见启动日志；共享地图和 PBStream 是不同文件，不能互相替代。

`shared_map.pgm` 可以直接打开查看。正式重载检查：

```bash
python3 scripts/map_roundtrip.py results/my_map/shared_map.yaml
```

程序会启动独立命名空间的 Nav2 map_server，读取保存地图并逐格比较，结束后清理自身节点。地图中灰色未知区应保持未知。

当前默认启动会重新建图，不自动从 PBStream 恢复任务。不要把一次探索得到的二维栅格图当成 Gazebo 的三维世界文件。

## 可选：第二个终端控制

正常用网页不需要第二个控制终端。如需命令行：

```bash
cd multi_robot
source ./env.sh
ros2 run fleet_control fleetctl explore
ros2 run fleet_control fleetctl pause
ros2 run fleet_control fleetctl formation triangle --x 0 --y 0 --yaw 0 --spacing 1.2
ros2 run fleet_control fleetctl formation row --x 0 --y 0 --yaw 0 --spacing 1.2
ros2 run fleet_control fleetctl formation column --x 0 --y 0 --yaw 0 --spacing 1.2
ros2 run fleet_control fleetctl status
```

只想看当前模式：

```bash
ros2 run fleet_control fleetctl status | python3 -c 'import json,sys; s=json.load(sys.stdin); print(s["mode"], s["message"])'
```

命令行和网页使用同一个调度器。不能通过 Gazebo 自带的 `/cmd_vel` 面板绕过三车的任务授权；本项目没有接入该单车遥控面板。

## 答辩或自动演示

先关闭本工程现有运行实例，再执行：

```bash
cd multi_robot
./demo.sh --headless --with-faults
```

程序自动启动后台，划分默认区域、探索、检查覆盖率 / 里程、保存、完成三种队形、恢复探索、检查地图重载，最后测试非法目标、急停、雷达中断和定位中断。运行结束自动清理后台。去掉 `--headless` 会同时打开 Gazebo。

结果在打印的 `runs/demo-<日期时间>` 下；查看 `acceptance.json`、`safety_acceptance.json`、`map_roundtrip.json`。正式演示中的覆盖率真值只被独立评估程序使用，不是机器人建图的输入。
