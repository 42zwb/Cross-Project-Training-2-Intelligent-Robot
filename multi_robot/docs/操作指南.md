# 三机器人操作手册

以下命令均从 `multi_robot` 目录运行。首次运行先按 [README](../README.md) 构建。同一主机一次运行一套 TurtleBot 仿真，单机和多机各使用自己的环境终端。

## 1. 网页操作

```bash
./run.sh
```

1. 打开终端显示的地址，默认 `http://127.0.0.1:8765`。在状态区确认三车本地链路就绪。
2. 点击“开始 / 恢复探索”。初始几何匹配阶段允许有限运动，建立共同坐标后进入三车分区探索。地图初期的未知区随车体观测逐步更新。
3. 探索完成或暂停停车后，在本轮共同地图的已知空闲区域选择巡逻航点或队形中心。队形可选三角形、横排、纵队。留足车体和墙体间距，观察三车分别完成停靠。
4. 点击“保存地图与运行结果”。保存后可检查 `shared_map.yaml`、`shared_map.pgm`、各车地图副本及 `frame.json`。
5. 在启动终端按 Ctrl+C 等待后台退出。关闭浏览器或显示端后，机器人仍执行自己的任务，可从 CLI 请求暂停或急停。

`./run.sh --gui` 同时显示 Gazebo 窗口。`./run.sh --no-dashboard` 使用纯 CLI。`./run.sh --seed 42 --spawn-layout 1` 选择另一个固定场景。自定义配置从 [fleet.yaml](../src/fleet_bringup/config/fleet.yaml) 复制后通过 `--config` 指定，`scene.seed: null` 使每次独立生成种子。

## 2. CLI、坐标与地图

另开终端加载本工程环境。按当前阶段选择命令。

```bash
source ./env.sh
ros2 run fleet_control fleetctl status
ros2 run fleet_control fleetctl explore
ros2 run fleet_control fleetctl pause
ros2 run fleet_control fleetctl estop
ros2 run fleet_control fleetctl clear-estop
ros2 run fleet_control fleetctl save --output results/my_peer_map
```

`status` 提供本轮 `coordinate_frame`。`fleetctl` 默认使用 `runs/latest.txt` 指向的运行目录。需要操作指定运行时，把 `--run-dir /路径/运行目录` 放在子命令前。解除急停后重新下发任务。

巡逻文件使用 YAML 或 JSON。以下为结构示例，把 `<本轮共同坐标系>` 替换成 `status` 的实际值，并按本轮地图选择空闲、可达的航点。`routes` 以机器人名作键，每个航点为 `[x, y, yaw]`，单位是米和弧度。

```yaml
coordinate_frame: "<本轮共同坐标系>"
cycles: 1
dwell: 0
goal_timeout: 120
routes:
  robot1:
    - [1.0, 0.5, 0.0]
    - [1.5, 0.5, 0.0]
```

```bash
ros2 run fleet_control fleetctl patrol --file /路径/本轮巡逻.yaml
ros2 run fleet_control fleetctl formation --help
```

队形命令依次指定 `formation triangle`、`formation row` 或 `formation column`，并用 `--x`、`--y`、`--yaw`、`--spacing` 给出同一共同坐标系下的中心、朝向和间距。任务转入安全执行前，各车会验证本车路线和通行授权。

```bash
python3 scripts/map_roundtrip.py results/my_peer_map/shared_map.yaml
```

该命令用地图服务器核对保存后的栅格语义。地图文件与 `frame.json` 保存本轮坐标信息，加载其他轮次的地图时需核对坐标系。

## 3. 自动演示和浏览器

先结束手动运行，再执行以下命令。

```bash
./demo.sh
```

演示脚本在一套仿真中自动探索、暂停恢复、巡逻、完成三种静态队形、急停及地图重载，随后退出。默认写入 `runs/demo-时间戳/`，可用 `--run-dir` 指定新目录。

浏览器验收在本机尚无 Playwright 时需要 `python3-pip`、Chromium 的系统依赖和下载权限。从 `multi_robot` 目录安装至隔离缓存。

```bash
browser_python="$HOME/.cache/tb4-fleet-browser-python"
python3 -m pip install --target "$browser_python" -r requirements-browser.txt
PYTHONPATH="$browser_python" python3 -m playwright install chromium
./demo.sh --with-ui-checks
```

如采用其他依赖目录，运行时设置 `FLEET_BROWSER_PYTHON` 指向该目录。浏览器预检先于仿真启动，检查依赖版本和实际 Chromium 运行。

| 文件 | 用途 |
| --- | --- |
| `demo-run.json`、`peer_demo.log` | 阶段、完成／失败／中断状态及运行日志 |
| `acceptance-functional-before-faults.json` | 功能阶段的独立评估 |
| `acceptance-after-faults.json` | 启用专项故障时的故障结束评估 |
| `acceptance.json` | 最终功能、身份、覆盖、碰撞及资源指标 |
| `peer-browser-acceptance.json`、`peer-monitor-acceptance.json` | 使用 `--with-ui-checks` 时的真实浏览器及监控退出检查 |
| `results/final/map_roundtrip.json`、`cleanup.json`、`detached_cleanup.json` | 地图恢复、退出和残留检查 |

## 4. 专项验收与离线复评

`./demo.sh --with-faults` 追加首场景故障注入与严格功能评估。全套发布核查需在同一冻结版本中完成首场景完整故障、九场景、两个配准反例、五轮冷启动和默认入口。先构建并准备浏览器依赖，再运行统一入口，把证据写入新目录。

```bash
source ./env.sh
bash scripts/build_tools.sh
release_dir="$PWD/runs/release-$(date +%Y%m%d-%H%M%S)"
python3 scripts/peer_release_acceptance.py --output "$release_dir"
```

前五个门禁全部通过后，报告进入 `awaiting_default_verification`。此时复查实际默认入口。命令中省略架构参数。

```bash
default_run="$release_dir/default-demo"
./demo.sh --with-ui-checks --run-dir "$default_run"
python3 scripts/peer_release_acceptance.py --output "$release_dir" \
  --finalize-default-run "$default_run"
```

查看 `release-acceptance.json` 各门禁状态、`source-freeze.json` 的源码／产物／测试摘要及证据 SHA-256 索引。可用 `--reuse-first-run` 或 `--reuse-matrix` 复用同冻结版本且证据齐全的既有结果。运行过的阶段以报告中的 `passed`、`failed` 或 `interrupted` 表示，尚未执行的阶段为 `not_run`。

已有运行可单独离线复评。输出到独立文件可保留原报告。

```bash
source ./env.sh
python3 -m fleet_control.relative_evaluate /路径/运行目录 \
  --output /路径/新评估.json
```

进程和网络专项保留受影响机器人授权、速度和车体运动证据。正式验收结束时检查所属进程残留、异常退出和证据齐全情况。

## 5. 排障

| 现象 | 检查方法 |
| --- | --- |
| 网页未打开 | 核对启动终端的端口、`launch.log` 与本轮 `manifest.json`。可用 `fleetctl status` 区分网页连接与机器人状态 |
| CLI 无状态 | 检查 `source ./env.sh`、域和分区，确认 `runs/latest.txt` 指向当前运行 |
| 车体处于初始化状态 | 检查雷达、私有 TF、配准状态及各车进程。共同坐标未接纳时授权只允许受限初始化运动 |
| 巡逻被拒绝 | 查看返回原因，核对 `coordinate_frame`、参与车辆在线状态、航点净空和路线可达性 |
| 队形动作未完成 | 查各车状态和当前任务，检查集合点周边自由空间及间距 |
| 浏览器预检失败 | 检查 `requirements-browser.txt` 对应版本、Chromium 安装、系统库及 `FLEET_BROWSER_PYTHON` |
| 退出后怀疑有残留 | 查看 `cleanup.json`、`detached_cleanup.json` 与下轮的 `startup_preflight.json`，通过启动终端管理所属进程 |
