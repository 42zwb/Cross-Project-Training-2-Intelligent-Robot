# 最终验收记录

验收日期：2026-10-21。结论：**本机默认场景的全部规定功能验收通过**。

以下为本机历史验收记录。原始 `runs/` 与 `results/` 产物未随源码仓库上传，克隆后需重新运行验收。

## 测试条件与样本

- Ubuntu 22.04、ROS2 Humble、Gazebo Fortress、CycloneDDS；机器 16 GiB 级内存、32 个逻辑 CPU。
- 三台 TurtleBot4 Lite、12×12 m 静态场地、0.05 m 栅格、640 线 / 10 Hz 激光、速度上限 0.2 m/s。
- 人工分区采用默认三个 X 轴条带；队形中心 `(0,0)`、朝向 `0 rad`、间距 `1.2 m`。
- 最终业务源码相同的 **3 次冷启动**；其中 **1 次最终版一键完整演示**，包含故障测试。另保存较早的完整正常流程记录 `runs/full-08-final`，不替代最终版证据。
- 正常流程包括：应用分区 → 三车探索 → 保存 → 三角形 → 横排 → 纵队 → 返回各区域 → 恢复探索 → 暂停 / 再保存。
- 退出、目标到位和地图覆盖率均依据实际数据 / 结果，不用固定等待时长代替。

## 安全、边界及故障注入

正常演示：

- 车体相对静态障碍的最小保守几何间隙 **0.257 m**。
- 车辆之间的最小保守几何间隙 **0.458 m**。
- 探索阶段区域违规采样 **0**；未检测到墙体、障碍或车辆碰撞。

故障注入各执行一次，停止 / 恢复的 PID 均限定为该次工程拥有的进程：

| 测试 | 实际动作 | 结果 |
|---|---|---|
| 非法队形 | 中心设为 `(20,20)` | 拒绝请求 |
| 急停 | 运动中锁定急停 | 三车停稳，后续位移采样均为 0 |
| 解除急停 | 解除后不发任务 | 保持待命，不自动恢复 |
| 雷达中断 | 暂停 robot1 激光桥进程 | 进入故障停车，三车停稳 |
| 定位中断 | 暂停 robot1 Cartographer 进程 | 进入故障停车，三车停稳 |
| 导航关键节点中断 | 探索中暂停 robot1 BT Navigator | 约 2.03 秒进入故障停车，停稳后三车位移采样均为 0 |

故障测试没有逐一对 robot2 / robot3 复做相同故障；采用同一门控逻辑，已核验三车共同停车。

证据：`safety_acceptance.json`、`node_failure_acceptance.json`、真值轨迹和对应事件日志。碰撞结果基于保守车体几何与真值轨迹评估，不是仅凭导航返回成功判断。

## 三车隔离、坐标与保存

`runtime_acceptance.json` 实际核验：三套 640 线扫描、各自里程计和帧名正确；每车原始扫描、里程计、原生控制话题各一个发布者；123 个 TF 子帧未发现重复父节点，三车车体 / 激光 / 左右轮均连接到 `map`。动态 TF 发布节点无同名重复。

早期底座独立测试 `runs/base-07/base_acceptance.json`：分别只控制一台车，实际前进约 0.54 m，另两车位移为 0；停止发指令后原生 0.5 秒超时机制使车辆停车。最终完整流程再次核验了三车的实际运动和隔离状态。

共享地图在真实 Nav2 map_server 中重载后，**57,600 个栅格逐格一致**：未知 3,941、空闲 50,448、障碍 3,211。未知编码没有变为空闲。三份 PBStream 均通过 Cartographer WriteState 服务生成。

证据：`map_roundtrip.json`、`map_server_roundtrip.log`、`shared_map.*`、`alignment.yaml`、`robot*.pbstream`。
