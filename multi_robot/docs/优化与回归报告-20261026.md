## 发现与修复

1. **网页按钮无响应的源码根因。** 旧页面 `onclick="command('explore')"` 与浏览器 `HTMLButtonElement.command` 字符串属性冲突。在真实 Chromium 156 中点击旧按钮，复现 `command is not a function`，请求未发送。改为独立 JS 与 `addEventListener`；操作响应放在任务状态区，增加超时反馈、待就绪控制和重复提交保护。该浏览器属性见 [MDN 文档](https://developer.mozilla.org/en-US/docs/Web/API/HTMLButtonElement/command)。
2. **取消与目标接受之间的竞争。** 旧目标发送超时或切换任务后，服务器可能稍后接受旧目标；现在为发送 Future 保留取消回调，迟到的已接受目标会被取消。重复开始探索不会撤销现有探索目标；任务队列仅保留最新请求。
3. **传感异常与边界保护。** 检查扫描元数据、测量上下限、非有限里程计/定位值，以及运动方向完全无有效观测的情况。任务代号改变时清除旧速度缓存。地图输入在数组分配前检查尺寸、分辨率、姿态及编码；规划将栅格外部视为不安全空间。
4. **运行实例识别。** 网页与验收请求校验运行目录标识，并对中文路径做 URL 编码。脚本读取本轮端口、显式传递运行目录；端口占用时在启动仿真前拒绝，且不覆盖有效的 `latest.txt`。
5. **保存和配置边界。** 限制并发保存请求，超时的 PBStream 请求释放客户端并报告失败；起点不得与静态障碍或墙体相交，分区起点余量与规划器车体余量一致。独立覆盖率评估按配置起点计算可达连通分量。
6. **文档与实际代码一致。** 当前统一队形判据为位置误差 ≤0.25 m、朝向误差 ≤15°、车心距离 ≥`2 × radius + 0.14 m`，稳定保持 3 s；控制器自身目标容差为 0.08 m / 0.10 rad。修正文档中的旧阈值，首次任意运动任务后锁定分区。

### 退出路径发现与处理

Smac 完整验收后的首次退出，在系统 `ros_gz_bridge` 0.244.26 的 robot2 雷达桥中观察到 `free(): corrupted unsorted chunks`、退出码 -6；后续定向复验也曾在 `/clock` 桥接进程观察到退出异常。异常发生于 SIGINT 退出阶段，任务与地图验收此前均通过；无残留进程。仅凭这些信息不能确认上游具体发生错误释放的位置。

最终停机顺序改为：先请求停车，只向本进程组且启动参数精确指向本轮 SDF 的 Gazebo 服务器发送 SIGINT；桥接与 ROS 节点保持存活，等待数据源退出和最后回调排空，再由 ROS launch 关闭其余节点。先前尝试暂停采样、逐个退出桥接的版本仍出现过 Gazebo 退出超时及桥接异常，未计入最终通过项。监督脚本现在记录异常子进程并返回失败，验收不会把这种退出算作成功。临时诊断配置已经撤除，系统桥接库没有被改写。

该处理是针对本机观测到的退出问题的项目级缓解；上游堆损坏的根因尚未定位。最终复验记录见下方，结论不延伸为所有驱动或所有长时间运行都不会发生退出异常。
