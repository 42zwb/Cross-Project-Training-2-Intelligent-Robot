## 修复内容

1. **队形验收门槛统一并增加车间距保护。** 首轮真实仿真中，Nav2 已报告目标完成，但机器人 1 的实际位置误差为 0.183 m；调度器原门槛是 0.15 m，而独立验收器使用 0.25 m，造成可接受队形被报为故障。现在调度器与真值评估共用同一判定函数：位置误差不超过 0.25 m、航向误差不超过 15°，且任意机器人中心距至少为 `2 × robot_radius + 0.14 m`（默认 0.50 m）。算法测试覆盖超限和车间距不足情形。
2. **收紧本地网页 API 输入。** 只接受精确 API 路由、`application/json` 对象请求和已知控制接口；路径查询参数仍可用于地图版本缓存；响应添加 `X-Content-Type-Options: nosniff`。服务仍只绑定 `127.0.0.1`，并保留 Origin 校验。
3. **补齐仓库忽略规则。** 根 `.gitignore` 排除多机本地 tf2 动态库、仿真结果、Python 缓存、ruff 缓存和 egg-info，避免误提交构建或运行产物。

此次完整验收也暴露了 Ctrl+C 后的清理问题：安全节点可能在 ROS context 关闭后再发布停车消息，多个 Python 节点把 context 关闭异常打印成未处理堆栈；监督脚本向整个进程组发 SIGINT 时，`ros2 launch` 还会再次向子进程发信号。修复如下：

- `scripts/supervise.py` 首先只向 `ros2 launch` 管理进程发 SIGINT，保留超时后的进程组清理兜底。
- `safety.py` 只在 ROS context 仍有效时发布最后的零速度指令；控制器原生命令超时仍提供停车兜底。
- `coordinator.py`、`dashboard.py`、`fleet_mapping/node.py` 和 `nav_ready.py` 仅在 context 已关闭时吞掉 ROS 关闭异常，正常运行中的异常仍会报出。

修复后在另一个隔离运行目录 `runs/shutdown-regression-20261021-02/` 让三车实际探索 22 秒，再于运动中按 Ctrl+C。三个机器人均有里程增长；`cleanup.json` 记录 `launch_exit=0`、残留子进程 `[]`；日志中没有 Python traceback、`RCLError` 或 `ExternalShutdownException`，网页端口释放。ROS 2 launch 默认在 5 秒后将未退出的子进程升级为 SIGTERM；这些节点随后均正常退出。该过程不是任务故障，且没有残留仿真进程。

修复后再次构建：4 个包成功；13 项测试及 tf2 锁回归通过。Python `compileall` 和两项目 shell 脚本 `bash -n` 通过。当前源码副本与 GitHub 工作副本一致（唯一目录差异为空的运行时 `worlds/` 目录，不含文件）。原始仿真结果仍在本机 `runs/`，未提交到仓库。
