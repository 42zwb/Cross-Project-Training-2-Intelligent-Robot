核查日期：2026-10-21。

## 1. 完成度结论

工程已经具备教程主体所需的环境、仿真、遥控、建图、地图保存、定位与自主导航实现，教程末尾清单中的 8 个 Python 功能脚本也都已实现并注册为 ROS2 可执行程序。本轮重新构建、13 项现有测试、无界面单机导航、缩短路线建图巡航和状态保存均通过。

但当前还不能认定为“教程全部内容已稳定验收”：本轮发现自建地图加载时未知区域被当成空闲区域的问题；RViz/Gazebo 的历史退出崩溃没有完成修复验收；实体手柄、默认完整路线、修正后的自建地图导航、多机器人等没有在本轮全部重跑。课程延伸中的视觉识别、额外规划算法和机械臂操作也没有实现。

不以一个没有统一权重的百分数代替验收结论。当前阶段是：**主体代码齐全，单机主要功能已实测跑通，完整稳定性和部分扩展验收仍未完成。**

## 3. 本轮发现的主要问题

### P1：保存地图重新加载后，未知区域被解释为空闲区域

`~/maps/warehouse_map.pgm` 的像素分布为：

| PGM 灰度 | 栅格数量 | 对应含义 |
| --- | ---: | --- |
| 205 | 171014 | 保存图像中的未知区域 |
| 254 | 89672 | 空闲区域 |
| 0 | 2184 | 障碍区域 |

原 YAML 中 `free_thresh: 0.25`。实际通过 `map_loader` 加载并读取 `/map` 后，消息中的分布是：

```text
未知 -1：0
空闲  0：260686
障碍100：2184
```

这说明地图虽能加载，但未知区域语义丢失。随后只在 `/tmp` 建立一份临时 YAML，将 `free_thresh` 改为 `0.196`，通过 `/map_server/load_map` 重新加载，服务返回 0，分布恢复为：

```text
未知 -1：171014
空闲  0：89672
障碍100：2184
```

因此当前不能仅凭“map_server active”就确认自建地图可正确复用。`room_map.yaml`、`tutorial_room.yaml` 也使用 `free_thresh: 0.25`，需要一并检查；本轮实际动态复现的是 `warehouse_map`。

建议优先修正已有地图元数据及保存流程，并增加保存前后未知/空闲/障碍分类一致性的回归检查。本轮没有修改原来的三份地图；用于对照的配置和新地图均生成在 `/tmp`。新地图保存时显式指定了 `free_thresh_default:=0.196`。

### P2：图形界面退出崩溃仍是未关闭的问题

`/var/crash/_opt_ros_humble_lib_rviz2_rviz2.1000.crash` 和 `/var/crash/_usr_bin_ruby3.0.1000.crash` 分别记录了 2026-10-14 14:57:28、14:57:34 的 Signal 11。Ruby 对应 `ign gazebo gui`。

这些是实际崩溃记录。本轮无界面运行通过，不能据此宣布图形窗口稳定性问题已解决，也不能从现有报告直接认定具体显卡驱动或某个源码函数就是根因。

### 需要补验或补齐的项目

1. 用修正后的自建地图完成重新定位与实际导航闭环；本轮导航成功使用的是官方 warehouse 地图，自建地图只进行了独立加载与分类对照。
2. 验证 Gazebo/RViz 的打开、持续建图、关闭、再次启动过程。
3. 明确 IMU 数据的提供方式；当前 Cartographer 不使用 IMU，现有雷达和里程计主线可以运行。
4. 接入实体手柄后核对按键、摇杆、使能键和断连停车。
5. 重新验证完整默认路线、四点巡航、动态障碍和双机器人并行导航。已有历史通过记录不等于本轮复测。
6. 仿真入口默认 `spawn_dock:=true`，导航入口默认 `false`，建图入口没有显式暴露并转发该选项；本轮建图通过“单独启动无充电座仿真 + start_sim:=false”验收。默认含充电座路线的车体实际位移需要另外核对。
7. PBStream 状态保存已通过；现有 Cartographer launch 没有提供恢复状态文件的参数，本轮未验收加载 PBStream 后继续建图。
8. `/etc/ros/rosdep/sources.list.d/20-default.list` 不存在，rosdep 尚未初始化；当前二进制依赖可运行，但自动依赖安装流程仍需整理。

## 5. 本轮实测记录

构建和测试：

```bash
source /opt/ros/humble/setup.bash
cd single_robot
colcon build --symlink-install --event-handlers console_direct+
source install/setup.bash
colcon test --packages-select turtlebot4_tutorial turtlebot4_cartographer \
  --event-handlers console_direct+
colcon test-result --all --verbose
```

结果：两个包构建成功；13 项测试通过，0 errors、0 failures、0 skipped。包含 11 项功能测试和 2 项代码规范测试；代码规范工具产生 2 条弃用警告，不是测试失败。另有 23 个 Python 文件 AST 解析、1 份工程 YAML、2 份 package.xml 解析通过，自定义 SDF 校验通过。

导航实测使用隔离的 ROS_DOMAIN_ID=81、IGN_PARTITION=tutorial_audit_20261021；自建地图独立加载使用域 82。建图实测使用域 83 和独立 Ignition partition。都使用 CycloneDDS，仿真不打开图形窗口。

导航到 `(0.5, 0, 0)` 的进程退出码为 0。结束后：

```text
Gazebo 车体世界坐标：x=0.2802786，y=0.0248344
轮式里程计：        x=0.2800909，y=0.0255550
AMCL/map 中的位置： x=0.2605196，y=-0.1088590
```

这确认了车体实际发生位移，而不是仅有里程计数值变化。配置的位置容差是 0.25 m，成功不代表车体中心精确等于目标坐标；本轮没有进行定位精度标定。

建图巡航实测：

```bash

ros2 launch turtlebot4_tutorial tutorial_simulation.launch.py \
  spawn_dock:=false rviz:=false model:=lite \
  gz_args:='warehouse.sdf -s -r -v 1'
ros2 launch turtlebot4_tutorial tutorial_mapping.launch.py \
  start_sim:=false rviz:=false
ros2 run turtlebot4_tutorial mapping_patrol --ros-args \
  -p side_length:=0.15 -p angular_speed:=1.0
```

以上是不同终端中的命令；核查时各终端使用了相同域和 partition。9 段动作全部执行，进程退出码 0。保存的临时地图为 468×364、0.05 m/像素；写入 PBStream 服务返回状态码 0。建图仿真速度约为真实时间的三分之一，不能仅以墙上时钟判断路线是否停滞。

## 6. 与旧说明的区别及后续顺序

当前 README 的验收日期为 2026-09-23。其多机器人巡航等历史记录仍可作为过去运行过的证据，但不能覆盖 10 月出现的图形界面崩溃，也没有检查到本轮发现的地图未知区域丢失问题。
