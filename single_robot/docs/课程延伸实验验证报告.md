验证日期：2026-10-21

平台：Ubuntu 22.04、ROS 2 Humble、Gazebo Fortress、TurtleBot4 Lite 仿真。

## 1. YOLOv8 + ROS 2

### 实现

`src/turtlebot4_tutorial/turtlebot4_tutorial/yolo_detector.py` 提供 `yolov8_detector` 节点：

- 默认订阅 `/oakd/rgb/preview/image_raw`，可用 `image_topic` 参数更换。
- 默认使用 COCO 预训练 `yolov8n.pt`、CPU、320 像素推理输入和 0.35 置信度阈值。
- 发布 `vision_msgs/Detection2DArray` 到 `/yolo/detections`，发布带框图像到 `/yolo/annotated`。
- 使用隔离的 `.venv-yolo`，并把 NumPy 固定为 1.26.4，以避开本机用户 Python 的 NumPy 2 与 ROS `cv_bridge`/OpenCV 组合冲突。

### 验证

安装环境中的版本为 NumPy 1.26.4、OpenCV 4.10.0、PyTorch 2.5.1+cpu、TorchVision 0.20.1+cpu、Ultralytics 8.3.40。`torch.cuda.is_available()` 返回 `False`；本次只验证 CPU 推理。

用 Ultralytics 官方示例 `bus.jpg` 直接推理，得到 6 个框：bus、4 个 person 和 stop sign。随后将同一图像通过 ROS `Image` 消息发布到测试输入话题，节点输出 `person`、`bus` 类别，并由 `/yolo/annotated` 收到 810×1080 的 BGR 标注图。仿真中的 `/oakd/rgb/preview/image_raw` 相机链路也启动成功；空旷的 warehouse 画面没有检测框。

使用方法见项目 README 的“11.1 TurtleBot4 相机上的 YOLOv8”。预测接口参考[Ultralytics Predict 文档](https://docs.ultralytics.com/modes/predict/)。

## 2. Nav2 Smac2D

`config/nav2_params.yaml` 保留 Navfn 为 `GridBased` 默认规划器，并注册 `Smac2D`。两个插件都在 planner server 生命周期中成功激活。

在 `ROS_DOMAIN_ID=101` 的 TurtleBot4 Lite warehouse 仿真中，对 `/compute_path_to_pose` 请求同一目标：`map` 坐标系下 `(x=0.5, y=0.0)`，`use_start=false`。两次 action 均以成功状态返回：

| planner_id | 路径点 | Nav2 返回的规划时间 |
| --- | ---: | ---: |
| `GridBased` / Navfn | 33 | 6 ms |
| `Smac2D` | 18 | 3 ms |

这只说明本次两条路径都可规划。路径点数受平滑、地图分辨率和目标影响，不能单凭一次结果说某规划器普遍更快或更优。Smac2D 适合本项目近似圆形的差速底盘；需要非圆形运动学时，应另行评估 Smac Hybrid-A*。D*、RRT* 不是这次安装或配置出来的功能。

Smac 规划器细节参考[Nav2 Smac Planner 文档](https://github.com/ros-navigation/navigation2/blob/main/nav2_smac_planner/README.md)。

## 3. MoveIt 2 抓取与放置

由于 TurtleBot4 Lite 只有移动底盘，抓取实验使用 Panda 机械臂模型和 MoveIt Task Constructor 官方 demo。系统账户没有 sudo 权限，因此 MoveIt、Panda 配置和 MTC demo 的 Debian 包下载后解压到工作区的 `.moveit-overlay`，没有注册或改写系统 dpkg 数据库。

启动 Panda mock ros2_control 和 MoveGroup 后，运行 `panda_mtc_task.launch.py execute:=true`。任务日志报告规划成功、轨迹执行完成；随后确认 Panda 关节状态回到 ready 姿态，碰撞物体保留在放置位置。该结果是 MoveIt 模拟控制器中的规划与执行，不是实体抓取。

MoveIt Task Constructor 流程参考[MoveIt Humble Pick and Place 教程](https://moveit.picknik.ai/humble/doc/tutorials/pick_and_place_with_moveit_task_constructor/pick_and_place_with_moveit_task_constructor.html)。

## 4. 构建与测试

完成修改后执行：

```bash
source /opt/ros/humble/setup.bash
cd ~/turtlebot4_ws
colcon build --packages-select turtlebot4_tutorial
source install/setup.bash
colcon test --packages-select turtlebot4_tutorial
colcon test-result --all --verbose
```

`colcon build` 成功；18 项测试通过，0 failures、0 errors。输出包含 2 条现有 SelectableGroups 弃用警告，不影响测试结果。新增 `test/test_advanced_planners.py` 检查默认 Navfn 仍在且 Smac2D 已注册。

## 未覆盖项

- 没有实体 OAK-D 相机、GPU、机械臂和夹爪，因此只做仿真与公开样例图验证。
- D*、RRT* 及 Smac Hybrid-A* 的实际机器人参数对比未做。
- YOLO 仅验证 COCO 预训练权重；没有训练或微调特定物品类别。
- 本机 MoveIt 使用用户目录 overlay；在有管理员权限的全新系统上还应独立验证 apt 安装流程。
