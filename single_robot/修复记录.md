## 已修复的项目

| 问题 | 处理结果 |
| --- | --- |
| 地图重新加载时未知区域变为空闲 | 三份旧 YAML 均先备份再修正 `free_thresh=0.196`；PGM 不变。增加工程 `map_saver` 保存入口，保存后验证元数据；`map_loader` 和导航启动会拒绝仍有此问题的地图 |

| 总入口可能不打开 RViz | 仿真子启动文件的 `rviz:=false` 泄漏到父启动文件；使用有作用域的 `GroupAction` 隔离配置，已验证总入口正常打开 RViz |
| RViz 关闭时段错误 | 软件渲染单独使用仍能复现崩溃，新栈落在 `rclcpp::CallbackGroup` 析构。默认配置避开原 Nav2 RViz 扩展组合，采用标准 `2D Goal Pose` 工具和 `goal_pose` 目标话题；建图与导航视图均实测正常退出 |
| Gazebo GUI 与服务器退出和渲染耦合 | 分成独立服务器与 GUI 进程；GUI 与 RViz 默认软件渲染，服务器独立运行。两次 Gazebo GUI 窗口关闭均正常退出，服务器能继续提供数据 |
| RViz 配置指向 `/opt/ros`，保存不便、建图显示 Nav2 unknown | 提供仿真、建图、导航三份工程配置，首次复制到用户目录，可保存。建图不加载 Nav2 控制面板，不默认显示密集 TF 线条 |
| 没有 IMU ROS 话题 | 补齐 Ignition IMU 系统、每台机器人的传感器话题、ROS 桥接与传感器 TF；实测 `/imu` 有数据且可关联到 `base_link` |
| 没有恢复 PBStream 的启动参数 | 建图入口和 Cartographer 入口增加 `load_state_filename`、`load_frozen_state`。修正布尔型 gflags 必须用 `-load_frozen_state=false` 形式传递的问题，已实际恢复并开启新轨迹 |
| 控制器更新周期快于仿真步进 | 工程控制参数使用 100 Hz，替代原 1000 Hz。参数在生成描述时引用工程副本，未改系统安装文件 |
| rosdep 未初始化，依赖声明不完整 | 使用用户目录初始化并更新 Humble 索引，`.bashrc` 设置 `ROSDEP_SOURCE_PATH`。移除无有效 rosdep 定义的 `ament_python` 构建工具依赖，保留正确的构建类型；补齐图像/YAML、桥接、建图、键盘与手柄依赖，依赖检查通过 |

## 更新后的操作方式

每个新终端先运行：

```bash
source ~/.bashrc
```

建图：

```bash
# 终端 1：保持运行
ros2 launch turtlebot4_tutorial tutorial_mapping.launch.py

# 终端 2：手动探索，或选择运行自动巡航
ros2 run turtlebot4_tutorial mapping_patrol
```

保存地图（建图尚在运行时，新终端执行）：

```bash
ros2 run turtlebot4_tutorial map_saver ~/maps/my_map
ros2 service call /write_state cartographer_ros_msgs/srv/WriteState \
  "{filename: '/home/bwz/maps/my_map.pbstream', include_unfinished_submaps: true}"
```

关闭建图后，用本轮实测的新地图导航：

```bash
# 终端 1：保持运行
ros2 launch turtlebot4_tutorial tutorial_navigation.launch.py \
  map:=/home/bwz/maps/warehouse_verified.yaml

# 终端 2：单目标
ros2 run turtlebot4_tutorial nav_action_demo 0.8 0.3 1.57

# 或四点巡航
ros2 run turtlebot4_tutorial nav_commander_demo --loops 1
```

也可以在 RViz 使用 `2D Goal Pose` 点击拖拽设置目标。RViz 关闭后单独重开：

```bash
ros2 launch turtlebot4_tutorial tutorial_rviz.launch.py mode:=navigation
```

恢复原始 SLAM 状态继续建图：

```bash
ros2 launch turtlebot4_tutorial tutorial_mapping.launch.py \
  load_state_filename:=/home/bwz/maps/warehouse_verified.pbstream \
  load_frozen_state:=false
```

上述验证使用相同仓库世界、原点附近重新生成的机器人。已经单独启动仿真时，建图或导航加 `start_sim:=false`，并保持实际生成位姿一致。不要同时启动建图和 AMCL 定位，因为它们都可能发布 `map → odom`。

## 仍需区分的边界

- 没有实体手柄，不能完成实体按键和断连验收；模拟 Joy 与停车逻辑测试已通过。
- 本轮没有重跑双机器人并行巡航。已用回归测试验证第二台机器人不会重复添加 Sensors 和 IMU 系统插件；历史双机运行记录仍保留。
- 默认控制器 100 Hz 低于仿真步进频率时可能打印 `slower` 警告；它与原先的“更新周期过快”错误不同。主动中断仿真服务器时的 `exit code -2` 是中断结果。
- RViz 首帧仍可能打印一次地图 GLSL sampler 提示，本轮显示和更新正常。[上游问题 #463](https://github.com/ros2/rviz/issues/463) 记录了相同现象；该提示未通过屏蔽日志的方式隐藏。
- YOLO、机械臂等教程延伸不属于本轮已知问题修复范围。
